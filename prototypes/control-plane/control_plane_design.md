## 1. 核心审美与信息减法准则（Linear / Raycast / Stripe Sail）

1. **砍掉 70% 说明书式废话文案**
   - 标题本身已自明（如 `概览`、`上游服务`、`工具目录`、`仓库绑定`、`连接客户端`、`请求日志`、`路由沙盒`、`访问与路由`），`SailSectionHeader` 与 `SailCardTitle` 默认传 `subtitle = ""`；优化后的 `SailSectionHeader` 在 `subtitle == ""` 时不留空隙，直接渲染利落的标题与右侧操作区。
   - 删掉表单底部、弹窗顶部、Tab 顶部的常识性说明（如“点击保存后生效”、“语义路由模型将按相关性打分”等）。仅保留高价值护栏提醒或空状态引导。

2. **去套娃与 Hairline Divider 列表**
   - **严禁卡片套小卡片**：容器内列表统一使用无外框的底部分割线行（`SailFlushCard` 内的细分割线行 / `SailDivider`，`1px solid #e3e8ee`），替代层层描边 + 圆角 + 阴影的小卡片堆叠。
   - **单行最多 3 个信息锚点**：列表行聚焦「主标识（+ 弱化从属名） / 清洗后一句话摘要 / 状态或风险开关」，次要元数据（`Actors`、`Tags`、`Revision`、`Adapter`）全部收进右侧详情检视面板。

3. **徽标降噪（Badge De-noising）**
   - **常规/在线/只读状态降噪**：使用 `SailQuietStatus(c, label, dotColor, textColor)`（6–7px 状态圆点 + `12px` 柔和灰字 `#697386`），不再铺满高对比度绿/蓝彩色胶囊。
   - **高饱和彩色仅留给关键风险与异常**：
     - 写操作风险：`RW` 保留柔和琥珀告警胶囊（`ToneWarning`）；
     - 错误与故障：连接失败、路由异常保留红/琥珀提示（`ToneDanger` / `ToneWarning`）。

4. **呼吸感与留白基线**
   - 页面级区块间距（Section Gap）：`24px`（主视口 `Padding(28, 32)`，`Gap(24)`）。
   - 卡片内边距（Card Padding）：`20px`（`SailCard` 默认 `Padding(20)`、`Gap(14)`）。
   - 正文行高：多行描述统一 `LineHeight(1.5)` ~ `1.55`，兼顾中英文混排清晰度。

### 1.1 表面与阴影层级

采用已确认的[控件阴影规范](../control-elevation/elevation_design.md)：选中导航和操作按钮弱化边框，用轻微向下的外阴影表达浮起；普通内容卡片更淡，列表行继续使用分割线；下拉浮层、弹窗和悬浮抽屉有独立的阴影层级。浅深色分别设置阴影透明度，按钮按住时撤去投影。对比见[阴影原型](../control-elevation/elevation.html)。

## 2. 上游 MCP `Description` 解析清洗与排版标准

真实上游 MCP / OpenAPI 工具的 `description` 常包含大量换行符、`###` 标题、`**粗体**`、`` `code` ``、`- ` / `* ` / `1.` 列表以及 `Args:` / `Parameters:` / `Returns:` 文档段，直接纯文本输出会糊成一团。

`ui_theme.go` 提供统一的解析与双场景渲染组件：

### 2.1 列表摘要：`CleanDescriptionSummary(raw string) string`

- 去除 Markdown 标记与文档分节噪声，提取简洁用途摘要。
- `SailDescSummary(c, raw, emptyFallback, maxLines)` 用于列表展示，限制行数并保留空描述的明确回退。

### 2.2 详情解析：`ParseStructuredDescription(raw string) StructuredDescription`

- `Lead`：首段用途；`Paragraphs`：补充段落。
- `Bullets`：要点；`Params`：参数名、类型与说明。
- `HasMoreRaw`：存在需展开查看的原文内容。

### 2.3 详情渲染：`SailDescriptionDetail(c, key, raw)`

保留结构化段落、行内代码/强调、要点和等宽参数名；长内容按需展开原文。上述名称对应 PR #6 合入后的原生实现，原型页面用于信息层级与交互参考。

## 5. 仓库绑定（Repo Scope 作用域）设计细则

1. **导航定位与顶部护栏**
   - 一级导航名固定为 **`仓库绑定`**（`repos`），位于 `工具目录` 与 `连接客户端` 之间，徽标显示已绑定仓库数。
   - 页面顶栏右侧保持克制：`启用仓库隔离拦截`（`enforce`）开关、`手动配置 Hook` 按钮与 `添加仓库` 主按钮。开启 `enforce` 后，缺少有效 `_gw_ctx` 凭证的请求返回 `403 scope_required`，严禁回退到全局读写池。

2. **矩阵总览与单仓库详情**
   - 顶部 `矩阵视图 / 单仓库详情` 切换，默认展示矩阵。切换控件左对齐，外框与背景仅包住两个按钮，按文案自然宽度收紧，不使用固定宽度，也不随父列拉伸铺满整行。矩阵横行是 `全局默认 *` 与已绑定仓库，纵列是真实上游 MCP 服务（排除演示服务，包含已停用服务）；未绑定观测仓库用轻量一键加入条展示。
   - 每列表头仅单行 `[真实品牌图标] 服务名`，复用 MCP 市场品牌资产；未知服务使用通用服务图标。无启用数量、描述或多行堆叠。长名称单行省略并提供完整提示；宽表整体横向滚动，表头与格子同步对齐。
   - 单元格只用二态勾选框表达仓库默认服务授权；不显示 RO/RW 或工具白名单。继承仓库显示全局默认的勾选；首次操作将继承授权复制为显式仓库规则，只改变目标服务。取消最后一个授权保存空规则，不能删除规则而重新继承。新增服务默认 `ro`，其他服务已有的 `rw` 和工具子集保持原样。
   - 勾选后立即保存，保存期间锁定该行；失败保留服务端原值并提示，可重试。详情中存在未保存修改时暂时禁用该行勾选，提示先在详情保存或重置，避免隐式提交其他编辑。
   - 行尾 `详情` 选中该仓库并切到 `单仓库详情`，继续编辑 RO/RW 与工具子集。跨页仓库跳转也直接进入详情。两种视图共用主题令牌，兼容浅色与深色。
   - **单仓库详情采用原有主从双栏**：
   - **左栏（280px `SailFlushCard`）**：
     - 首行固定 `全局默认`（`repo_key = "*"`）：未绑定新仓库命中此层，开箱默认 `grants: []`（`默认无服务`）。
     - `已绑定仓库` 分组：每行严格控制在 3 个锚点以内（仓库名、`RemoteHint` 短标识或 `本地仓库`、绑定服务数），按本机 Git `CommonDir` 自动归并所有 `git worktree` 与子目录。
     - `最近请求 · 未绑定` 分组：仅展示携带有效 Hook 签名凭证的观测仓库，行尾提供一键 `绑定`。
   - **右栏（选中作用域详情）**：
     - **锚点头部**：展示仓库名、`CommonDir` / 目录根路径与移除操作（Web 端支持从已观测列表一键绑定或手动录入名称与 `git_common_dirs` / `root_paths`，不依赖原生系统目录选择器）。
     - **仓库默认服务 `repo_key`**：按两层优先级（`具体仓库规则 > 全局默认 *`）求值；细分割线列出授权服务，服务描述经 `CleanDescriptionSummary` 降噪；右侧紧凑切换 `只读 RO` / `读写 RW`（仅 `RW` 渲染琥珀胶囊），支持按需展开勾选 `tool_ids` 工具子集。

3. **手动配置 Hook 与三页闭环**
   - `手动配置 Hook` 检视器支持切换 6 个客户端，展示目标配置路径、`gateway-hook` 二进制路径及可一键粘贴的配置/插件代码片段。
   - `路由沙盒` 提供模拟仓库（`管理员全量` / `未绑定新仓库 (*)` / 已绑定仓库）下拉项，请求携带 `sim_scope` 并联动刷新候选池计数。
   - `请求日志` 检视器结构化展示 `detail.scope`（客户端、仓库、根路径、命中规则、验证状态），未绑定仓库可就地一键绑定，「在沙盒中重放」自动携带原请求的仓库作用域。

## 原生辅助窗口标题栏

macOS 更新等原生辅助窗口沿用内容区背景：标题栏透明，不显示标题栏与内容区之间的分隔线。保留原生红黄绿窗口按钮、标题、拖动区域与内容布局；不以全尺寸内容模式改变现有间距。明暗主题均应呈现连续的窗口表面。

## 6. 上游服务就绪度（Readiness）与凭据/连接状态规范（#63）

1. **三层状态解耦（拒绝用「已启用」冒充绿灯）**
   - **启用开关（`Enabled`）**：仅由行尾或详情右上角的 Switch 表达服务是否对外开启，不再单独把 `Enabled == true` 渲染为绿色圆点。
   - **当前可用状态（Readiness）**：按严格优先级推导为 5 档互斥状态，贯穿「概览 KPI / 概览服务列表与抽屉 / 上游服务列表 / 服务详情头部」：
     1. `已停用`（灰点，无彩色胶囊）：`Enabled == false`；
     2. `缺少凭据`（红点 + `缺少凭据` 危险胶囊）：`Headers` / `Env` 引用的 `${ENV_VAR}` 在当前进程环境与系统钥匙串中均未配置；
     3. `连接异常` / `调用失败`（红点 + 危险胶囊）：最近一次连接检查失败，或在上次检查通过之后发生了未恢复的上游凭据/鉴权/连接类 `invoke` 失败；
     4. `待验证` / `未开放工具`（琥珀圆点 + 琥珀胶囊）：尚未执行连接检查、配置或凭据指纹变更导致检查过期（`Stale`），或已连通但开放工具数为 `0`；
     5. `就绪`（绿点，详情使用 `SailQuietStatus` 柔和文字 `就绪`，不铺绿色胶囊）：已启用 + 凭据齐全 + 当前指纹检查通过 + 无未恢复调用故障 + 开放工具 `> 0`。
   - **历史检查记录（`LastChecked`）**：独立保留真实检查时间戳供追溯；当处于 `缺少凭据`、`调用失败` 或 `Stale` 状态时，严禁将历史检查渲染为绿色圆点，统一弱化展示为 `待复测 · <时间>` 或 `历史通过 · <时间>`。

2. **首屏诊断与免重启修复闭环**
   - **首屏告警直达**：打开服务详情（默认停留在「工具白名单」子 Tab）时，若存在凭据缺失、调用失败、连接异常、待验证或 `0` 工具开放，直接在元数据卡片下方渲染单条精准提示框与就地动作按钮（`填写凭据`、`立即测试连接`、`仅开放只读`），无需翻找子 Tab。
   - **明确缺失变量与双路径修复指引**：凭据缺失提示直接列出变量名（如 `GITHUB_TOKEN`），说明可在「连接与认证配置 → 服务凭据」中填入保存至系统钥匙串（免重启立即生效），或导出进程环境变量后重启网关；全程掩码输入，界面与日志绝不回显密钥明文。
   - **常驻探活与一键恢复**：服务详情顶栏常驻 `测试连接` 按钮；「服务凭据」卡片底部提供 `仅保存` 与主按钮 `保存并测试连接`，补齐凭据并测通后自动刷新状态并恢复 `就绪` 绿点。

3. **列表分诊（Triage）——把状态展示变成待办清单**
   - **分组与排序**：5 档 Readiness 收敛为 4 个处理桶：`需处理`（缺少凭据 / 连接异常 / 调用失败）→ `待验证`（待验证 / 未开放工具）→ `就绪` → `已停用`；「全部」视图按桶排序并渲染轻量分组标题，页头摘要优先显示红色 `N 个需处理`。
   - **筛选维度**：顶部分段控件使用状态桶（`全部 / 需处理 N / 待验证 N / 就绪 N / 已停用 N`），不再按 `MCP Stdio / MCP HTTP / HTTP REST` 传输协议筛选；协议名与缺失变量名并入搜索字段。
   - **单行状态表达，拒绝三重红色**：异常行仅保留「红/琥珀圆点 + 彩色状态词 + 等宽变量名或原因」一行，不再叠加状态胶囊；启用中的缺凭据服务追加弱化后果 `· Agent 调用将失败`。
   - **就地动作**：行尾操作按钮随状态切换（`填写凭据` 跳详情配置页并聚焦输入框、`测试连接` / `重新测试` 原地探活、`开放只读`），就绪行不放按钮；整行点击进入详情，用 `›` 提示可点，删除每行重复的 `管理详情` 按钮。存在 ≥2 个可探活服务时提供 `全部测试连接 (N)` 批量入口，只弹一条汇总 Toast。
   - **降噪**：列表内启用开关使用小号 `switch-quiet`，颜色沿用全局 accent 与其他页面一致；写操作数从琥珀 `写 ×N` 胶囊降为工具数旁的 `N 可写` 弱文本，避免与 `待验证` 琥珀语义撞色；不可调用服务的工具数以更浅灰呈现并提示「上次同步的工具数」。
   - **入口与导航**：`粘贴 MCP JSON / OpenAPI 导入` 收进 `添加上游服务` 分体按钮下拉（含 `从 MCP 市场添加`）；侧栏 `上游服务` 计数在存在需处理服务时显示红色需处理数，否则显示启用数。
