# 安全模型与信任边界

网关通过调用通道发现、读取和执行工具，通过管理通道配置服务、凭据和仓库规则。公共健康检查只提供存活状态和实例识别信息。管理端可从 `/api/auth/me` 和 `/api/bootstrap` 的 `security_mode` 判断部署模式。

## 受控边界模式（Shared / Remote Boundary）

在独立 OS 账户或远端主机下运行网关，配置 [`GATEWAY_AUTH_FILE`](../examples/access.json) 并通过 HTTPS 暴露服务。运行账户独占网关数据目录、服务凭据和仓库签名密钥。Agent 只持有分配给自己的 Gateway 访问令牌。共享部署使用令牌哈希或保留前缀 `GATEWAY_` 下的令牌环境变量，避免把网关凭据放入服务可展开的普通进程环境变量。

网关从访问令牌或登录 Cookie 建立 Principal，并按 Principal 的组、服务、工具范围和写权限授权。请求提交的 `actor` 无法改变 Principal，管理员也受其工具 ACL 约束。开启仓库隔离后，调用还要通过仓库策略。网关在服务端向上游出示凭据，并在向调用方返回数据之前对已知凭据和已配置的字段脱敏。独立运行账户或远端主机使 Agent 无法直接读取网关的密钥和审计数据库。仓库隔离需要可信签名方，并依赖网关能够访问和校验的工作区路径。工作区签名密钥由受控边界内的网关和受信任 Hook 保管。

调用活动按服务端确认的 Principal 归因，并记录仓库作用域。审批功能接入后，请求者和审批者必须由服务端分别鉴权，请求者不得审批自己的请求。M0 交付身份、作用域和审计基础，审批流及其禁止自批的检查由后续阶段实现。

## 本地护栏模式（Local Guardrail）

桌面端和 Agent 通常在同一 OS 用户下运行。桌面端每次启动内嵌网关时生成随机管理令牌，只在该桌面进程内保留。桌面 HTTP 客户端使用 `X-Gateway-Admin-Token` 访问管理 API。Agent 通过 loopback 调用工具，其配置和环境中没有该令牌。启用管理令牌后，服务配置、凭据配置、仓库规则等管理路由要求有效令牌。这个通道也为后续审批操作提供管理凭据边界。

无界面后端通过服务进程的 `GATEWAY_ADMIN_TOKEN` 启用相同的管理校验。未设置令牌的本地后端保留兼容行为，loopback 请求可调用管理路由。无令牌时仍执行仓库隔离规则。桌面端附接已有实例时不会取得该实例的内存令牌。

本地模式用于防范误操作、提示注入和通过网关请求实施的越权。请求路径执行管理校验、仓库策略和响应脱敏。共享同一 OS 用户的进程可能有权读取同一用户的文件和凭据、调用已经登录的外部 CLI，或利用该用户的权限接触网关进程。本地护栏的作用域是网关路径。仍持有目标服务凭据的本地 CLI 需要配合登出，才能把调用收敛到网关。

## 仓库隔离和凭据处理

- `ScopeEnforce=true` 时，四个 REST 调用路由都要求调用方提供作用域凭据。普通调用方提供有效的 `X-Gateway-Scope`。管理员也可显式申请模拟视角。POST 请求携带 `sim_scope` 对象，GET 请求用 `sim_scope` 查询参数传仓库键。空仓库键表示全貌视角，审计记录标记为 `bypass`。指定仓库的模拟记录标记为 `simulated`。当前 `gatewayctl` 调用命令不签发作用域凭据，开启拦截后会收到 `403 scope_required`。
- 本地 `/api/auth/me` 对 loopback 返回 200，由 `authenticated` 表示是否验证了管理令牌。共享模式下，该接口要求有效的共享身份。
- 服务的环境变量和请求头引用专属凭据库。普通进程环境变量保留临时覆盖能力。大小写不同的 `GATEWAY_` 前缀均禁止从网关进程环境展开，服务仍可显式保存自身同名凭据。
- 工具响应在字段投影之前处理配置凭据、已知敏感字段和活跃 OAuth 令牌。服务所有者使用字段规则标记业务敏感数据。

接口细节见 [HTTP API 契约](api/README.md)，仓库签名和权限求交过程见 [架构文档](architecture.md)。
